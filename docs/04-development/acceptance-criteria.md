# R1 验收标准

> 文档状态：Draft for Review  
> 版本：0.1.0  
> 日期：2026-10-31  
> 原则：**可执行、可观察、可复现**；不以“页面已完成”代替业务闭环。  
> 关联：[R1 范围](../01-product/mvp-scope.md)、[测试策略](testing-strategy.md)、[产品需求](../01-product/product-requirements.md)

## 1. 验收定义

### 1.1 Pass / Fail

- **Pass**：在干净环境按步骤执行，结果与预期一致；证据留存。
- **Fail**：任一步骤失败、出现 P0/P1 缺陷、或无法复现。
- **Blocked**：环境/依赖缺失；必须修复环境后重跑，不能记为 Pass。

### 1.2 缺陷等级

| 等级 | 定义 | 发布影响 |
|---|---|---|
| P0 | 数据泄露/丢失、审批错误、无法登录、跨用户/部门/项目越权 | 阻断 |
| P1 | 核心闭环不可完成、权限错误、审计缺失 | 阻断 |
| P2 | 非核心功能缺陷/体验问题 | 可带已知问题发布 |
| P3 | 文案/样式小问题 | 可发布 |

### 1.3 验收环境

- 干净数据目录 + LMDB 初始化 + seed。
- 至少 2 个组织 fixture（用于 IDOR），但生产单组织。
- 至少 6 个用户：org_admin、system_admin、auditor、dept_manager、member A、member B。
- 至少 2 个项目：private、organization。
- 浏览器：Chrome/Edge 最新；移动视口 390×844。
- 网络：本地/内网。

## 3. AC-01 项目管理闭环

**目标**：创建项目 → 添加成员 → 创建任务 → 分配负责人 → 更新进度 → 完成任务 → 项目归档。

### 3.1 前置

- org_admin 已创建组织、部门、用户。
- PM 是 active 用户，有 `project:create`。
- member A/B 是 active 用户。

### 3.2 步骤与预期

| # | 操作 | 预期 |
|---|---|---|
| 1 | PM 登录，创建项目“官网改版”，短键 `WEB`，私有 | 201；项目 `planning`；PM 为 owner；成员列表含 PM；审计 `project.created` |
| 2 | 添加 member A 为 member，member B 为 viewer | 成员列表正确；A/B 收到通知；审计记录 |
| 3 | PM 启动项目 | 状态 `active`；成员通知 |
| 4 | PM 创建任务“首页改版”，分配给 A，优先级 high，截止日期未来 | 任务编号 `WEB-1`；A 的“我的待办”出现；A 收到通知 |
| 5 | A 将任务拖到“进行中”，进度 40 | 状态 `in_progress`，进度 40；刷新保持 |
| 6 | A 评论“接口已联调” | 评论出现；PM 收到通知（非自己） |
| 7 | A 将进度改为 100 并确认完成 | 状态 `done`，进度 100，`completed_at` 有值；从 A 待办移除 |
| 8 | PM 尝试完成项目 | 成功；项目 `completed`；项目只读 |
| 9 | PM 归档项目 | 状态 `archived`；默认项目列表隐藏；详情只读 |
| 10 | 尝试在归档项目创建任务 | 409 `PROJECT_ARCHIVED`，无数据写入 |
| 11 | org_admin 查看操作日志 | 能查到项目创建/成员/任务/状态变更，含 actor/requestId |

### 3.3 边界

- [ ] 项目短键重复 → 409，提示可操作。
- [ ] 有未完成任务时完成项目 → 409，返回数量。
- [ ] owner 不能直接移除；转让后旧 owner 变 manager。
- [ ] 移除有未完成任务的成员 → 409。
- [ ] 非成员访问私有项目 → 404。
- [ ] 组织可见项目非成员只读；不能创建任务/评论。
- [ ] 看板非法迁移 → 409，UI 回滚。
- [ ] 并发两个浏览器移动同一任务 → 一方 409。
- [ ] 100 并发创建任务 → 编号唯一、连续。
- [ ] 评论超过 15 分钟编辑 → 409。

### 3.4 证据

- E2E 录屏/截图；
- API 响应/DB 查询；
- 审计日志截图；
- 并发测试报告。

## 4. AC-02 OA 审批闭环

**目标**：提交申请 → 审批处理 → 通过或驳回 → 状态更新 → 历史记录保存。

### 4.1 前置

- 请假/用印模板 active。
- member A 的直属上级是 dept_manager；部门负责人是 org_admin（或另一人）。
- 审批链至少 2 步，便于验证顺序。

### 4.2 通过路径

| # | 操作 | 预期 |
|---|---|---|
| 1 | A 发起请假，填写类型/时间/原因，保存草稿 | 申请 `draft`，仅 A 可见 |
| 2 | A 提交 | `pending`；实例 `running`；第 1 步 `active`；第 1 审批人收到通知；审计 `application.submitted` |
| 3 | 第 1 审批人打开待我审批 | 看到申请；可查看表单/附件/历史 |
| 4 | 第 1 审批人通过，填写“同意” | 第 1 步 `approved`；第 2 步 `active`；第 2 审批人收到通知 |
| 5 | 第 2 审批人通过 | 实例/申请 `approved`；A 收到通知；`completed_at` 有值 |
| 6 | A 查看审批历史 | 提交 + 两次通过，顺序/人/时间/意见完整；不可编辑 |
| 7 | org_admin 查看全部申请 | 可见；不能修改状态/历史 |

### 4.3 驳回路径

| # | 操作 | 预期 |
|---|---|---|
| 1 | 新申请提交，审批人驳回但不填意见 | 422，要求 10–500 字 |
| 2 | 填写意见并驳回 | 申请 `rejected`；后续步骤不激活；A 收到通知 |
| 3 | A 复制新建 | 新草稿预填原字段；原申请不变；新审批实例 |

### 4.4 撤回/转交

- [ ] 无审批动作时 A 撤回 → `withdrawn`；审批人待办消失；通知；不可再提交。
- [ ] 已有通过记录后撤回 → 409。
- [ ] 当前审批人停用前未转交 → 409；转交后新审批人可处理；历史含 `reassign`。
- [ ] 转交给停用/申请人/自己 → 422。
- [ ] 非当前审批人审批 → 403/409；重复审批 → 409；并发只成功一次。

### 4.5 模板/表单

- [ ] 发布新版本后，新申请用新版本；旧进行中实例不变。
- [ ] 同类型第二个 active 模板 → 409。
- [ ] 无 active 模板提交 → 409。
- [ ] 审批人为空/本人/停用 → 提交失败，指出步骤。
- [ ] 请假时间重叠 → 409，显示冲突区间。
- [ ] 用印无附件 → 422；附件可被审批人下载。
- [ ] 五类表单必填/长度/日期/金额/份数边界正确。
- [ ] 重复提交（同 Idempotency-Key）只创建一条；同 key 不同 body → 409。

### 4.6 可见性

- [ ] 申请人只看自己的；当前/历史审批人看参与过的；部门负责人不自动看全部；org_admin 全量；auditor 仅摘要。
- [ ] 其他用户/部门/项目越权 → 404。
- [ ] 审批历史不可编辑/删除；停用用户显示已停用。

### 4.7 证据

- E2E 录屏；
- 申请/实例/步骤/记录 DB 快照；
- 并发测试；
- 可见性矩阵测试报告。

## 5. AC-03 权限管理闭环

**目标**：创建用户 → 分配角色 → 授予权限 → 验证访问范围 → 记录关键操作。

### 5.1 步骤

| # | 操作 | 预期 |
|---|---|---|
| 1 | org_admin 创建部门“研发部”，设置负责人 | 部门树正确；负责人显示 |
| 2 | org_admin 创建用户 A（研发部，member） | 账号创建；临时密码只显示一次；A 首次登录强制改密 |
| 3 | org_admin 创建自定义角色“研发主管”，授予 `application:read:all` + `department_tree` | 角色创建；权限预览正确 |
| 4 | 给 A 分配该角色 | 立即生效（下一请求） |
| 5 | A 查看申请列表 | 仅研发部及子部门；不含其他部门 |
| 6 | A 尝试访问全组织设置/角色管理 | 403；菜单不显示 |
| 7 | A 尝试访问其他部门私有项目/受限文档 ID | 404，无数据泄露 |
| 8 | org_admin 撤销角色 | A 下次请求失去该范围 |
| 9 | auditor 查看操作日志 | 能查到用户创建/角色分配/撤销，含 actor/时间/requestId |
| 10 | system_admin 查看项目正文 | 403/404（默认不读业务） |

### 5.2 边界

- [ ] 账号重复 → 409；弱密码/临时密码错误 → 422。
- [ ] 停用自己 → 409；最后一个 org_admin → 409。
- [ ] 当前审批人未转交时停用 → 409。
- [ ] 自定义角色不能授予创建者没有的权限。
- [ ] system_admin 不能授予 org_admin。
- [ ] 项目私有：非成员 404；组织可见：只读。
- [ ] 文档 ACL：无权限 404。
- [ ] 审计员只读；无编辑/删除按钮/API。
- [ ] 角色变更立即生效。

### 5.3 证据

- 权限矩阵测试（表驱动）；
- 多用户/部门/项目 IDOR 报告；
- 角色/审计 DB 快照。

## 6. AC-04 文档管理闭环

**目标**：上传文档 → 分类 → 授权 → 检索 → 下载 → 版本记录。

### 6.1 步骤

| # | 操作 | 预期 |
|---|---|---|
| 1 | A 上传 PDF“服务合同”，标题/描述，选择分类“合同/2026”，标签“重要” | 201；版本 1；当前版本；SHA-256 记录 |
| 2 | 设置 visibility=restricted | 仅 A 可见 |
| 3 | 授权研发部 view | 研发部成员可见；其他部门不可见 |
| 4 | 研发部成员 B 搜索“服务合同” | 结果含该文档；其他部门搜索不到 |
| 5 | B 下载 | 成功；文件名/类型正确；审计记录下载 |
| 6 | A 上传新版本（备注） | 版本 2；当前版本 2；版本 1 仍可下载 |
| 7 | A 归档文档 | 状态 archived；默认列表隐藏；只读 |
| 8 | A 删除文档 | 软删除；默认列表/搜索隐藏；审计保留 |

### 6.2 边界

- [ ] 伪造扩展名/超大文件/HTML/SVG/EXE → 415/413，不落盘。
- [ ] 路径穿越文件名 → 安全存储 key，不越界。
- [ ] 无 ACL 用户直接下载 → 404。
- [ ] 项目文档继承项目成员 view；非成员 404。
- [ ] 组织文档全员可读；restricted 不继承。
- [ ] 撤销部门 ACL 后立即失去访问。
- [ ] 并发上传版本 → 版本号唯一，冲突 409。
- [ ] 版本不可修改/删除；当前版本指向正确。
- [ ] 搜索先 ACL 过滤，不泄露标题/大小。

### 6.3 证据

- E2E 录屏；
- 文件 SHA-256 校验；
- ACL 矩阵；
- 版本列表截图。

## 7. AC-05 横切能力

### 7.1 认证/会话

- [ ] 未登录访问任意 API → 401，无数据。
- [ ] 会话空闲/绝对过期 → 401；登录后回原页面。
- [ ] 改密/重置/停用/强制下线 → 所有会话撤销。
- [ ] 登录失败 5 次锁定 15 分钟；响应不泄露账号存在性。
- [ ] 临时密码登录只允许改密；改密后进入工作台。
- [ ] Cookie 属性 HttpOnly/SameSite 正确；本地 HTTP 不设 Secure。

### 7.2 CSRF/XSS/注入

- [ ] 缺失/错误 CSRF token 的写请求 → 403，无副作用。
- [ ] 跨 Origin 写请求 → 403。
- [ ] 评论/标题/描述中的 `<script>`/事件属性不执行。
- [ ] Markdown 链接 `javascript:` 被拒绝。
- [ ] 搜索/排序参数不能注入键/原型污染；非法排序字段 422。
- [ ] 错误响应无堆栈/存储路径。

### 7.3 组织隔离/权限

- [ ] 跨用户/部门/项目 IDOR 全端点 404。
- [ ] 列表查询不返回越权数据。
- [ ] 具体资源越权 404；功能无权限 403。
- [ ] 管理员不能代批；只能转交。
- [ ] 审计员只读；system_admin 默认不读业务正文。

### 7.4 审计/通知

- [ ] 登录、用户/角色/权限、项目/任务状态、申请提交/审批/转交、文档上传/授权/删除、配置变更均有审计。
- [ ] 审计不可通过 API 修改/删除；敏感字段不落日志。
- [ ] 通知与业务同事务；待办/角标一致；失效链接提示。
- [ ] 通知点击仍校验权限。

### 7.5 四态/响应式

- [ ] 每个主页面有加载/空/错误/无权限状态。
- [ ] 390px 视口可完成登录、查看待办、审批、任务状态更新；无横向滚动。
- [ ] 键盘可完成登录、审批。
- [ ] 色彩对比/焦点可见（axe 无 critical/serious）。

## 8. AC-06 非功能

### 8.1 性能

| 场景 | 目标 | 证据 |
|---|---|---|
| 任务列表（5 万任务） | P95 ≤300ms | 压测报告 |
| 工作台（500 用户/10 万申请） | P95 ≤500ms | 压测/日志 |
| 审批详情 | P95 ≤300ms | 压测 |
| 看板 500 任务 | 可操作，无卡死 | 手工/E2E |
| 25MB 上传 | 不 OOM，60s 内（视网络） | 手工/日志 |

允许记录环境限制导致的偏差；由人工决定是否接受。

### 8.2 运行/存储

- [ ] Windows 本机从零启动：Node 进程 + SPA + LMDB + `data/`，无 Docker/数据库服务。
- [ ] 默认只监听 `127.0.0.1`；本机浏览器访问正常；不对局域网默认开放。
- [ ] 显式改 `HOST` 后，受信局域网设备可访问；风险提示存在。
- [ ] 普通进程 `start.cmd` 启动；`Ctrl+C`/关闭进程可停止；无 Windows 服务注册。
- [ ] `data/init` 创建目录/打开 LMDB/seed 成功；健康检查 ready。
- [ ] 单实例锁：第二个进程启动被拒绝。
- [ ] 强杀进程后重启，LMDB 恢复且数据一致。
- [ ] 索引重建成功，计数/样本正确。
- [ ] 不提供自动/异地备份、备份保留/加密/恢复 UI（按最新决策）。
- [ ] 不要求反代/HTTPS/Caddy/IIS；本地 HTTP 可运行。
- [ ] 部署文档可让第二人按步骤完成。
- [ ] 回滚：应用版本回退；schemaVersion 迁移前向策略明确，无自动备份回滚。

### 8.3 安全

- [ ] 全部 [安全验收清单](../03-technical/security-design.md#14-安全验收清单) 通过。
- [ ] 依赖高危漏洞为 0 或有人工接受记录。
- [ ] 生产 Swagger 不公开；错误无堆栈。
- [ ] 上传/下载鉴权；文件不在 Web 根目录。
- [ ] 数据目录/文件目录不暴露公网。

### 8.4 兼容性

- [ ] Chrome/Edge 最近 2 major 正常。
- [ ] Safari/Firefox 基本可用（至少登录/审批/任务）。
- [ ] iOS Safari/Android Chrome 审批可用。
- [ ] 360px 最小视口不破版。

## 11. 豁免规则

- P0/P1 不允许豁免。
- P2 可带已知问题发布，但必须有：影响、规避、修复计划、人工签字。
- 性能/兼容性偏差可豁免，但必须记录实测值与接受理由。
- 安全项不允许“以后再说”；至少完成基线。
