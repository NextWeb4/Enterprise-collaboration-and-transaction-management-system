## 1. 一句话定义

**把项目、任务与行政审批放进同一个工作日**：面向通用组织的轻量级协同与事务管理平台。

## 2. 背景与问题

通用型组织通常同时使用三类工具：

1. 项目管理/任务工具：解决“事情怎么推进”；
2. OA/审批工具：解决“事情怎么被授权、被记录”；
3. 表格与群聊：解决“信息怎么传”。

工具割裂带来四个具体问题：

| 问题 | 典型表现 | 业务后果 |
|---|---|---|
| 工作入口分散 | 任务在一个工具，请假/用印在另一个，通知在群里 | 员工每天切换 3–5 个入口，遗漏待办与审批 |
| 项目与审批脱节 | 项目要采购/用印，审批记录无法回链项目 | 无法回答“这个项目卡在哪个审批” |
| 权限与组织脱节 | 项目成员、部门、角色各自维护 | 离职/转岗后权限残留，越权难发现 |
| 过程不可追溯 | 任务进度只在口头，审批历史可被覆盖 | 复盘与审计缺证据 |

大型 ERP 套件可以覆盖这些问题，但实施重、模块多、学习成本高；纯项目管理工具又缺少组织、审批、权限与审计。**市场空隙是“轻量但治理完整”**。

## 3. 产品定位

### 3.1 定位陈述

对于需要同时管理**项目执行**与**日常审批**的通用型组织，`collab-office` 是一个轻量级 OA + 项目管理平台。它用统一工作台聚合待办、审批、通知和项目动态，用可追溯的审批与权限模型保证治理，而不引入 ERP 的财务、供应链、制造等重型模块。

### 3.2 目标用户

| 维度 | 描述 |
|---|---|
| 组织规模 | 首版设计目标 20–500 名活跃用户；不设硬性行业限制 |
| 典型行业 | 软件/互联网、专业服务、教育、公益、贸易、轻制造的管理与项目团队 |
| 典型角色 | 员工、部门负责人、项目负责人、组织管理员、系统管理员、审计员 |
| 使用场景 | 项目推进、任务分派、请假/出差/外勤/用印/通用事务审批、组织与权限管理、文档沉淀 |
| 不适用 | 需要完整财务核算、供应链、生产制造、CRM 的大型企业；需要复杂 BPMN 流程编排的组织 |

### 3.3 用户要完成的工作（Jobs to be Done）

1. 当我开始一天工作时，我想在一个页面看到**必须由我处理**的任务和审批，而不是逐个系统查找。
2. 当我要推进一个项目时，我想快速建项目、拉成员、分任务，并看清谁在做什么、什么逾期了。
3. 当我要请假/出差/用印时，我想用符合组织规则的表单提交，并知道现在卡在谁那里。
4. 当我作为负责人时，我想只看到我权限范围内的数据，并能追溯到每一次关键操作。
5. 当我作为管理员时，我想用组织、角色、数据范围表达“谁能看什么、做什么”，而不是逐人配置。

## 4. 产品愿景与原则

### 4.1 愿景

让一个组织在**一个工作日视图**内完成“做事、求授权、留记录”，不需要在多个系统间搬运上下文。

### 4.2 产品原则

1. **闭环优先于功能数量**：每个模块必须能走完一个真实业务闭环，否则不做。
2. **一个工作台，三层信息**：今天要做什么（待办/审批）→ 正在推进什么（项目）→ 组织如何运转（管理）。
3. **默认简单，例外可控**：默认流程固定、字段精简；复杂规则通过角色/模板配置，不做万能低代码。
4. **权限可见、可解释**：每个“看不到/不能操作”的页面都要说明原因，而不是空白。
5. **历史不可篡改**：审批与审计只追加；业务数据可更正，但必须留痕。
6. **桌面优先，移动可用**：复杂配置在桌面完成；审批、任务状态、查看详情在手机可用。
7. **不复制任何产品的界面**：参考信息架构与交互原则，视觉与组件组合自主设计。

## 5. 核心价值

| 价值 | 对用户 | 对组织 |
|---|---|---|
| 统一入口 | 一次登录看到待办、审批、通知、最近项目 | 提高日活与事项闭环率 |
| 项目 + OA 一体 | 任务与审批互相回链 | 项目卡点可定位，审批有业务上下文 |
| 轻量治理 | 角色 + 数据范围 + 项目角色 + 文档 ACL | 权限可解释、离职转岗可回收 |
| 过程留痕 | 审批历史、操作日志、登录记录 | 可审计、可复盘、降低口头扯皮 |
| 低运维 | Windows 本机 Node + 本地数据目录，无需数据库服务 | 不承担数据库/容器/中间件运维 |

## 6. 产品范围

### 6.1 P0：R1 核心

| 模块 | 能力 |
|---|---|
| 工作台 | 我的待办、待我审批、消息通知、最近项目、工作概览 |
| 项目管理 | 项目创建/编辑、成员、状态、任务、看板、进度、评论 |
| OA 办公 | 请假、出差、外勤、用印、通用事务、审批流程、审批历史 |
| 组织管理 | 组织架构、部门、员工、岗位、角色、权限 |
| 系统管理 | 用户、角色权限、登录记录、操作日志、系统配置 |
| 文档中心核心 | 上传、分类/标签、授权、检索、下载、版本记录（完整规划，不做人为最小闭环拆分） |

### 6.2 P1：扩展

| 模块 | 能力 | 说明 |
|---|---|---|
| 文档中心增强 | 版本恢复、在线预览、全文检索、批量操作 | 建立在完整文档中心之上 |
| 日程与协同 | 个人日历、项目日程、会议、提醒 | 首版不做 |
| 数据分析 | 项目/任务完成率、逾期率、审批耗时、部门工作量、报表导出 | 首版只做工作台概览计数 |
| 流程增强 | 会签/或签、条件分支、转交、委托、加签 | 需重新评估引擎 |
| 集成 | 邮件、企业微信/钉钉、SSO、Webhook | 按客户需求排序 |

### 6.3 明确不做

- 低代码/表单设计器/代码生成器；
- 完整 ERP（财务、采购、库存、制造、CRM）；
- 即时通讯、音视频会议；
- 甘特图、任务依赖、工时、冲刺/迭代、OKR；
- 多组织 SaaS 计费与跨组织协作；
- 移动原生 App、Electron、离线模式；
- AI 自动审批/智能排期。

## 7. 信息架构

### 7.1 全局布局

```text
┌──────────────────────────────────────────────────────────────┐
│ 顶栏：组织名 / 全局搜索(P1) / 快速新建 / 通知 / 用户菜单        │
├──────────────┬───────────────────────────────────────────────┤
│ 侧边栏 240px │ 工作区（面包屑 + 页面标题 + 内容）              │
│ 工作台       │                                               │
│ 项目         │                                               │
│ OA 审批      │                                               │
│ 文档         │                                               │
│ 日程 (P1)    │                                               │
│ 数据 (P1)    │                                               │
│ ─────────    │                                               │
│ 组织管理     │                                               │
│ 系统管理     │                                               │
└──────────────┴───────────────────────────────────────────────┘
```

- 侧边栏可折叠为 64px 图标栏；移动端变为抽屉。
- 顶栏固定 56px；通知未读数以红点呈现，不使用声音。
- “快速新建”只放高频动作：新建项目、新建任务、发起申请、上传文档。
- 管理入口按权限显示；无权限的菜单不渲染，直接访问 URL 返回 403 页面。

### 7.2 主导航与页面

| 一级 | 二级/页面 | 主要用户 |
|---|---|---|
| 工作台 | 总览、我的待办、待我审批、通知 | 全员 |
| 项目 | 项目列表、项目详情（概览/任务/看板/成员/设置） | 全员/项目成员 |
| OA 审批 | 申请中心、发起申请、我的申请、待我审批、审批模板（管理员） | 全员/审批人/管理员 |
| 文档 | 全部文档、分类、标签、文档详情 | 全员（按 ACL） |
| 日程 (P1) | 我的日历、项目日历、会议 | 全员 |
| 数据 (P1) | 项目/任务/审批/部门报表 | 管理者/审计员 |
| 组织管理 | 组织架构、部门、员工、岗位、角色、权限 | 组织管理员 |
| 系统管理 | 用户、角色权限、登录记录、操作日志、系统配置 | 系统管理员/审计员 |

## 8. 角色化工作台

工作台不是四套页面，而是**同一布局下的模块组合与数据范围差异**：

| 工作台变体 | 首屏重点 | 额外模块 |
|---|---|---|
| 员工 | 我的待办、待我审批、通知 | 最近项目、本周完成 |
| 部门负责人 | 待我审批、部门逾期任务、部门成员负载 | 部门项目进度、审批耗时 |
| 项目负责人 | 我负责项目的健康度、逾期任务、待验收任务 | 成员负载、近期截止 |
| 管理员 | 待处理审批（若兼审批人）、异常登录、权限变更提醒 | 组织概览、系统配置入口 |

判定规则：按用户权限组合与主要角色取**可见模块并集**，不根据单一角色硬编码页面。详细规则见 [用户角色](user-roles.md) 与 [权限模型](../02-business/permission-model.md)。

## 9. 关键体验指标

### 9.1 北极星指标

**每周闭环事项数（Weekly Closed Work Items, WCWI）**  
= 每周完成的任务数 + 每周进入终态的申请数（通过/驳回/撤回）。

选择理由：同时覆盖项目与 OA 两条主线，能反映“事情是否真的完成”，而不是登录次数或页面浏览量。

### 9.2 辅助指标

| 指标 | 目标（试点期） | 说明 |
|---|---|---|
| 激活率 | ≥ 70% | 新组织 7 天内完成组织配置、首个项目、首个任务、首个审批 |
| 周活跃/月活跃 | ≥ 50% | 试点组织 |
| 任务按时完成率 | ≥ 60% | 有截止日期的任务 |
| 审批中位耗时 | ≤ 1 个工作日 | 从提交到终态，自然小时口径 |
| 审批一次通过率 | 观察项，不设目标 | 避免为了指标放松审批 |
| P95 API 延迟 | ≤ 300ms | 常规列表/详情，不含文件上传 |
| 5xx 率 | < 0.5% | 生产 |
| 关键操作审计覆盖率 | 100% | 状态变更、授权、登录、导出 |

不把“页面数、功能数、代码行数”作为成功指标。

## 10. 设计语言与交互规范

### 10.1 视觉方向

- **气质**：克制、专业、信息密度适中；避免大面积渐变、玻璃拟态、装饰性插画。
- **主色**：深蓝 `#2563EB`（操作/链接）；成功 `#16A34A`；警告 `#D97706`；危险 `#DC2626`；中性色使用冷灰。
- **字体**：系统 UI 字体栈（`-apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`）；数字使用 tabular numerals。
- **圆角**：卡片/输入 8px，按钮 6px；不使用超大圆角。
- **间距**：4/8/12/16/24/32 的 4 倍数体系。
- **图标**：Ant Design Icons；同一动作全站同一图标。
- **深浅色**：首版只做浅色；深色模式 P1。

以上 token 在实现时映射到 Ant Design `ConfigProvider`，不直接散落十六进制颜色。

### 10.2 布局规范

| 场景 | 规范 |
|---|---|
| 列表页 | 标题 + 筛选栏 + 表格 + 分页；筛选条件可重置；空状态有主行动 |
| 详情页 | 头部摘要（标题/状态/负责人/操作）+ 内容区 + 右侧元信息（桌面） |
| 创建/编辑 | 简单表单用抽屉（≤ 8 字段）；复杂表单用整页（项目、申请、文档） |
| 确认 | 破坏性操作必须二次确认，说明影响；不使用浏览器 `confirm` |
| 反馈 | 成功用 message；异步失败用页面内 alert + 可重试；表单错误定位到字段 |
| 批量操作 | 首版只做任务批量状态/删除（管理员），不做跨页全选 |

### 10.3 四类页面状态

每个数据页面必须实现：

1. **加载**：骨架屏（表格/卡片）或局部 Spin；超过 300ms 才显示，避免闪烁。
2. **空**：说明“为什么空 + 下一步做什么”，如“还没有项目，创建第一个项目”。
3. **错误**：可读错误 + 重试；保留筛选条件；不把堆栈暴露给用户。
4. **无权限**：说明缺少什么权限、可联系谁；不渲染敏感数据；不伪装成 404（除非安全需要）。

### 10.4 响应式

| 断点 | 行为 |
|---|---|
| ≥ 1200px | 完整侧栏 + 双栏详情 |
| 768–1199px | 侧栏折叠；表格横向滚动；详情单栏 |
| < 768px | 侧边栏抽屉；列表卡片化；审批/任务详情单栏；主操作固定底部 |

首版不承诺手机端完成组织/权限配置；但必须能查看待办、审批、任务详情和执行通过/驳回。

### 10.5 可访问性

- 目标 WCAG 2.1 AA 的关键项：键盘可达、焦点可见、对比度 ≥ 4.5:1、表单 label 关联、错误可被读屏读取。
- 状态不能只用颜色表达，必须同时有文字/图标。
- 所有图标按钮必须有 `aria-label`。

## 11. 竞品与参考边界

| 参考 | 借鉴 | 不借鉴 |
|---|---|---|
| Linear | 快速操作、命令菜单、任务详情的专注感 | 不复制其视觉、快捷键体系、专有交互资产 |
| Plane | 项目/工作项/视图/周期的信息架构 | 不使用其代码、数据库结构、AGPL 资产 |
| AppFlowy | 文档与块编辑器的内容组织 | 不做本地优先/协同编辑 |
| n8n | 流程节点的可视化表达 | 不做通用自动化编排 |
| Twenty | 对象/记录/视图的元数据思路 | 不做通用对象建模平台 |

完整分析见 [参考产品研究](../05-research/reference-products.md)。所有参考仅用于设计研究，不复用核心业务代码、数据库结构或完整产品架构。

## 12. 约束、假设与风险

### 12.1 约束

- 个人独立研发 + AI 辅助，首版工期以“周”计，必须控制范围。
- 单机部署优先，不引入微服务/中间件。
- 首版中文、单组织、桌面优先。
- 所有技术结论需有依据，不确定项标记待确认。

### 12.2 关键风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 范围膨胀（P0+文档+管理后台） | 延期、闭环不完整 | 以四条闭环为发布门禁；P1 严格延后 |
| 审批模型过度简化 | 真实组织不适用 | R1 明确顺序单审批人；P1 评估增强 |
| 权限组合复杂 | 越权/漏权 | 统一 AuthorizationService + 权限矩阵测试 |
| 组织隔离遗漏 | 严重数据事故 | 所有仓储强制 org_id + IDOR 测试 |
| 单机文件存储 | 扩容/容灾有限 | 存储适配器 + 本地目录；不做备份，多实例前再评估 |
| 个人开发疲劳/上下文丢失 | 质量下降 | AGENTS.md、决策记录、切片交付、自动化测试 |

## 13. 成功的样子

试点组织在上线 4 周后：

- 80% 以上员工每周至少登录 3 次；
- 项目负责人能在 1 个页面回答“项目是否按期、谁卡住了”；
- 员工发起请假/用印后，能在工作台看到当前审批人和历史；
- 管理员能在 5 分钟内完成新员工开户、角色分配与权限验证；
- 任何一次审批结果都能追溯到人、时间、意见与模板版本；
- 没有因为权限配置错误导致的数据泄露事故。
