## 3. M0：身份与工作台

### US-001 首次登录并修改临时密码

**作为** 新员工（MEM）  
**我想要** 用管理员给的临时密码登录，并被要求设置新密码  
**以便** 我的账号安全，且能开始工作

**追踪**：FR-SYS-01、安全设计  
**前置**：管理员已创建账号；账号 active；临时密码未过期。

**验收场景**

```gherkin
场景: 首次登录强制改密
  假设 我使用临时密码登录
  当 凭证正确
  那么 系统进入强制改密页，不允许访问其他页面
  当 我提交 12 位以上、非弱密码的新密码
  那么 系统撤销旧会话、创建新会话并进入工作台
  并且 审计记录“首次改密”事件
```

```gherkin
场景: 临时密码错误
  假设 我输入错误密码
  当 连续失败达到 5 次
  那么 账号锁定 15 分钟
  并且 页面只提示“账号或密码错误”，不暴露账号是否存在
```

**边界**：临时密码只展示一次；改密后旧密码立即失效；新密码不得与临时密码相同。

### US-002 按角色看到差异化工作台

**作为** 登录用户  
**我想要** 工作台只显示与我职责相关的模块  
**以便** 不被无关信息干扰，也不越权看到数据

**追踪**：FR-WB-01～05、权限模型  
**前置**：用户拥有不同角色/组织关系。

**验收场景**

```gherkin
场景: 普通成员工作台
  假设 我是普通成员，没有待审批
  当 我打开工作台
  那么 我看到我的待办、最近项目、通知、本周概览
  并且 不显示部门/组织管理模块
```

```gherkin
场景: 部门负责人工作台
  假设 我是研发部负责人，有 2 条待审批
  当 我打开工作台
  那么 待我审批模块排在前列并显示数量 2
  并且 概览包含本部门逾期任务数，不包含其他部门
```

**边界**：模块按权限并集显示；无权限模块不渲染；直接访问 URL 返回 403 页面。

---

### US-003 未登录/会话过期时被安全拦截

**作为** 系统  
**我想要** 在会话无效时拒绝访问并引导登录  
**以便** 未授权用户无法读取任何业务数据

**追踪**：安全设计、FR-SYS-01  
**前置**：用户未登录或会话已过期/被撤销。

**验收场景**

```gherkin
场景: 会话过期
  假设 我的会话因空闲超时被撤销
  当 我请求任务列表接口
  那么 返回 401，不返回任何任务数据
  并且 前端跳转登录页，登录后回到原页面
```

```gherkin
场景: 已停用用户
  假设 我的账号被管理员停用
  当 我发起任意请求
  那么 返回 401，且不泄露停用原因给非管理员
```

## 4. M1：项目与任务

### US-004 创建项目并成为负责人

**作为** MEM  
**我想要** 创建一个项目并设置名称、短键、可见性  
**以便** 开始组织团队工作

**追踪**：FR-PRJ-01  
**前置**：组织允许成员创建项目。

**验收场景**

```gherkin
场景: 成功创建
  假设 我填写名称“官网改版”、短键“WEB”、可见性“私有”
  当 我提交
  那么 项目创建成功，状态为“规划中”
  并且 我成为项目 owner，出现在项目成员列表
  并且 审计记录项目创建
```

```gherkin
场景: 短键重复
  假设 已存在短键 WEB 的项目
  当 我使用 WEB 创建新项目
  那么 返回 409，提示“项目短键已被使用”
  并且 不创建任何项目数据
```

**边界**：短键创建后不可改；结束日期早于开始日期被拒绝；名称重复允许。

### US-005 添加项目成员并分配项目角色

**作为** PM  
**我想要** 搜索同事、添加为成员并设置角色  
**以便** 团队可以协作，且权限适当

**追踪**：FR-PRJ-02  
**前置**：我是项目 owner；项目未归档。

**验收场景**

```gherkin
场景: 添加成员
  假设 我搜索到 active 用户“李四”
  当 我添加他为 member
  那么 他出现在成员列表，能查看项目并创建任务
  并且 他收到站内通知
```

```gherkin
场景: 不能移除 owner
  假设 项目 owner 是我
  当 我尝试移除自己
  那么 请求被拒绝（409），提示先转让 owner
```

```gherkin
场景: 成员有未完成任务时移除
  假设 成员王五有 3 个未完成任务
  当 我移除王五
  那么 返回 409，并列出 3 个任务
  并且 成员关系保持不变
```

**边界**：不能添加停用用户/外组织用户；owner 唯一；转让 owner 后旧 owner 变 manager。

---

### US-006 推进项目状态并归档

**作为** PM  
**我想要** 启动、暂停、完成、取消和归档项目  
**以便** 项目生命周期清晰，历史可追溯

**追踪**：FR-PRJ-03  
**前置**：我是 owner/manager。

**验收场景**

```gherkin
场景: 完成项目
  假设 项目内没有 todo/in_progress/in_review 任务
  当 我将项目标记为“已完成”并填写备注
  那么 项目状态变为 completed，所有成员收到通知
  并且 项目变为只读
```

```gherkin
场景: 有未完成任务时不能完成
  假设 项目还有 2 个进行中任务
  当 我尝试完成项目
  那么 返回 409，提示“还有 2 个未完成任务”
  并且 项目状态不变
```

```gherkin
场景: 归档
  假设 项目已完成
  当 我归档项目
  那么 项目从默认列表隐藏，详情只读
  并且 不能恢复到进行中
```

**边界**：归档只能从 completed/cancelled；取消需原因；取消时可选择同时取消未完成任务。

**作为** PM  
**我想要** 创建任务、设置优先级/截止日期并分配给成员  
**以便** 工作责任到人

**追踪**：FR-TSK-01  
**前置**：项目 active；我是项目成员且有分配权限（owner/manager）。

**验收场景**

```gherkin
场景: 创建并分配
  假设 项目短键为 WEB，已有 11 个任务
  当 我创建任务“首页改版”并分配给李四
  那么 任务编号为 WEB-12
  并且 李四收到通知，任务出现在他的“我的待办”
```

```gherkin
场景: 分配非成员
  假设 张三不是项目成员
  当 我把他设为负责人
  那么 返回 422，提示先添加为项目成员
```

**边界**：任务编号并发不重复；截止日期早于开始日期被拒绝；viewer 不能创建任务。

### US-008 在看板上拖动任务

**作为** 项目成员  
**我想要** 把任务从“待处理”拖到“进行中”或“已完成”  
**以便** 快速反映工作进展

**追踪**：FR-TSK-02、FR-TSK-03  
**前置**：项目 active；我有该任务更新权限。

**验收场景**

```gherkin
场景: 拖到进行中
  假设 任务 WEB-12 当前为 todo
  当 我把它拖到 in_progress 列
  那么 状态更新为 in_progress，列计数同步变化
  并且 刷新页面后顺序保持
```

```gherkin
场景: 拖到已完成
  假设 任务进度为 40
  当 我把它拖到 done
  那么 状态变为 done，进度自动变为 100
  并且 任务从“我的待办”移除
```

```gherkin
场景: 并发冲突
  假设 另一位成员已先移动了该任务
  当 我拖动旧版本任务
  那么 返回 409，页面刷新该任务并提示“任务已被更新”
```

**边界**：非法迁移被拒绝；viewer 不能拖拽；归档项目不能拖拽。

---

### US-009 更新任务进度

**作为** 任务负责人  
**我想要** 更新进度并在完成后标记完成  
**以便** 团队看到真实进展

**追踪**：FR-TSK-03  
**前置**：任务未完成；我是创建者/被分配者/PM。

**验收场景**

```gherkin
场景: 进度 100 触发完成
  假设 任务进度为 80，状态为 in_progress
  当 我把进度改为 100
  那么 系统提示“是否标记为已完成”
  当 我确认
  那么 状态 done，进度 100，completed_at 记录当前时间
```

```gherkin
场景: 重新打开
  假设 任务已完成
  当 我把状态改为 todo 并提交进度 0
  那么 任务重新打开，进度 0，completed_at 清空
  并且 审计记录重新打开
```

**边界**：非 done 状态进度不能为 100；done 状态进度必须 100；项目完成率同步变化。

**作为** 项目成员  
**我想要** 在任务下讨论、修正信息  
**以便** 决策与上下文留在任务里

**追踪**：FR-TSK-04  
**前置**：我是项目成员且非 viewer。

**验收场景**

```gherkin
场景: 发表评论
```

### US-011 项目概览回答“项目是否健康”

**作为** PM  
**我想要** 在项目详情看到完成率、逾期数、待验收数  
**以便** 快速判断是否需要干预

**追踪**：FR-WB-05、FR-PRJ-03、FR-TSK-03  
**前置**：我是项目成员。

**验收场景**

```gherkin
场景: 健康摘要
  假设 项目有 20 个有效任务，12 个完成，3 个逾期，2 个待验收
  当 我打开项目概览
  那么 完成率显示 60%，逾期 3，待验收 2
  并且 点击数字可跳转到对应筛选列表
```

**边界**：取消任务不计入分母；无任务时完成率 0；归档项目只读展示。

## 5. M2：OA 审批

### US-012 提交请假申请

**作为** MEM  
**我想要** 填写请假类型、时间、原因并提交  
**以便** 获得上级批准

**追踪**：FR-OA-01、FR-OA-06  
**前置**：请假模板 active；审批人可解析；无时间重叠。

**验收场景**

```gherkin
场景: 提交成功
  假设 我选择年假，起止时间为 11 月 3 日 09:00 至 11 月 4 日 18:00
  当 我填写原因并提交
  那么 生成申请，状态 pending
  并且 当前审批人收到通知，申请出现在其“待我审批”
```

```gherkin
场景: 时间重叠
  假设 我已有一条 pending 的年假覆盖 11 月 3 日
  当 我提交重叠的请假
  那么 返回 409，显示冲突区间
  并且 不生成审批实例
```

**边界**：时长 0.5 天步长；结束早于开始被拒绝；交接人不能是自己。

---

### US-013 审批通过或驳回

**作为** MGR  
**我想要** 查看申请详情并通过/驳回，填写意见  
**以便** 及时处理团队事务

**追踪**：FR-OA-06、FR-OA-07  
**前置**：我是当前步骤审批人；实例 running。

**验收场景**

```gherkin
场景: 通过最后一步
  假设 我是最后一步审批人
  当 我点击通过并填写“同意”
  那么 申请状态 approved，实例 approved
  并且 申请人收到结果通知，历史记录新增一条
```

```gherkin
场景: 驳回
  假设 我是当前审批人
  当 我驳回但不填意见
  那么 返回 422，要求填写 10–500 字驳回意见
  当 我填写意见并确认
  那么 申请 rejected，后续步骤不再激活
```

**边界**：非当前审批人 403；重复审批 409；审批人不能是申请人；管理员不能代批。

### US-014 申请用印并上传文件

**作为** MEM  
**我想要** 提交用印申请并上传待盖章文件  
**以便** 行政核对后安排用印

**追踪**：FR-OA-04  
**前置**：用印模板 active。

**验收场景**

```gherkin
场景: 缺少附件
  假设 我未上传待用印文件
  当 我提交
  那么 返回 422，提示“请上传待用印文件”
```

### US-015 撤回尚未审批的申请

**作为** MEM  
**我想要** 在没人审批前撤回申请  
**以便** 修改后重新提交

**追踪**：FR-OA-06  
**前置**：申请 pending；尚无 approve/reject 记录。

**验收场景**

```gherkin
场景: 撤回成功
  假设 我的申请还没有任何审批动作
  当 我点击撤回并确认
  那么 申请状态 withdrawn，实例 withdrawn
  并且 当前审批人的待办中移除
```

```gherkin
场景: 已审批后不能撤回
  假设 第一步已通过
  当 我尝试撤回
  那么 返回 409，提示已有审批记录
```

**边界**：撤回后不能再次提交，只能复制新建；撤回需二次确认。

### US-016 管理员转交卡住的审批

**作为** OA  
**我想要** 把当前审批转交给其他 active 用户  
**以便** 审批人离职/长期不在时流程不中断

**追踪**：FR-OA-06、FR-SYS-01  
**前置**：我是组织管理员；实例 running；有 `workflow:reassign`；填写原因。

**验收场景**

```gherkin
场景: 转交当前步骤
  假设 当前审批人已停用
  当 我把步骤转交给新审批人并填写原因
  那么 新审批人收到通知，可处理
  并且 历史新增 reassign 记录，原审批人保留
```

```gherkin
场景: 转交给停用用户
  假设 目标用户已停用
  当 我提交转交
  那么 返回 422，不改变步骤
```

**边界**：只能转交当前步骤；不能转交给申请人；必须写审计；不改变步骤序号。

### US-017 发布新审批模板版本

**作为** OA  
**我想要** 修改审批步骤并发布新版本  
**以便** 新申请使用新流程，旧申请不受影响

**追踪**：FR-OA-06  
**前置**：我是组织管理员；模板存在。

**验收场景**

```gherkin
场景: 新版本不影响进行中实例
  假设 旧版本有 1 步，已有 5 个进行中申请
  当 我发布 2 步的新版本
  那么 新申请使用 2 步
  并且 旧申请仍按提交时的 1 步快照运行
```

```gherkin

```

### US-019 复制被驳回的申请重新提交

**作为** MEM  
**我想要** 复制被驳回的申请并修改后重新提交  
**以便** 不重复填写全部内容

**追踪**：FR-OA-01～05  
**前置**：原申请 rejected/withdrawn；我有查看权限。

**验收场景**

```gherkin
场景: 复制新建
  假设 我的请假申请被驳回
```

```gherkin
  假设 我不是私有项目成员
  当 我请求该项目任务 UUID
  那么 返回 404，不返回标题/状态/负责人

```

```gherkin
场景: 跨部门申请

  那么 返回 404
```

```gherkin
场景: 受限文档
  假设 我不是文档 owner，也不在 ACL 中
  当 我请求文档下载
```

### US-030 重复提交不产生重复审批

**作为** 申请人

**以便** 不产生重复审批

**验收场景**

```gherkin
  并且 两个响应返回同一申请 ID
```

```gherkin

```

**边界**：幂等键 24 小时内有效；不同用户/不同请求体复用同一键返回 409；审批用版本/行锁而不是幂等键。
