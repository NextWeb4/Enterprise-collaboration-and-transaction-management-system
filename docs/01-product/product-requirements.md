## 1. 文档约定

### 1.1 优先级

- **P0**：R1 必须交付，缺失则不能验收。
- **P1**：首版后扩展，当前不开发。
- **P2**：远期，不承诺。

### 1.2 需求 ID

`FR-<模块>-<序号>`。模块：WB 工作台、PRJ 项目、TSK 任务、OA 审批、ORG 组织、SYS 系统、DOC 文档、CAL 日程、AN 分析。

### 1.3 通用规则（适用于所有页面/接口）

1. **单组织数据边界**：任何查询/写入只作用于本部署；跨用户/部门/项目/文档越权视为不存在（404）。
2. **权限**：先校验权限码，再校验资源关系/数据范围，最后校验业务状态；默认拒绝。
3. **加载/空/错误/无权限**：每个页面必须实现四态，文案可行动，不暴露堆栈。
4. **分页**：列表默认 20 条/页，可选 10/20/50/100；最大 100；返回 `total`。
5. **排序**：默认按业务时间倒序；任务/审批支持明确排序项；不提供任意字段排序。
6. **日期时间**：API 使用 UTC ISO 8601；界面按组织时区展示；纯日期不带时区。
7. **乐观锁**：项目、任务、文档、申请更新携带 `version`；冲突返回 409 并提示刷新。
8. **审计**：创建、更新、状态变更、删除、授权、登录、导出均写审计；密码/令牌/文件内容不写日志。
9. **通知**：只做站内通知；关键事件在同一 LMDB 写事务内写入通知记录。
10. **删除**：默认软删除；审批、审计不删除；删除操作必须二次确认。
11. **文本格式**：任务描述/评论/文档说明使用 Markdown；渲染时做 XSS 白名单过滤；不支持原始 HTML。
12. **文件**：除文档中心外，申请附件复用同一存储适配器；单文件上限 25MB（可配置），不允许可执行文件。
13. **错误码**：业务错误返回稳定 `code`（如 `TASK_STATE_INVALID`），前端按 code 做提示，不解析自然语言。
14. **无权限反馈**：菜单不渲染；直接访问 URL 返回 403 页面并说明所需权限；具体资源越权返回 404。
15. **移动端**：审批、任务状态更新、通知查看必须可用；组织/权限配置不要求移动端。

## 3. 工作台（WB）

### FR-WB-01 我的待办

**功能说明**：聚合分配给当前用户、尚未完成的任务，按截止日期与优先级排序，支持快速进入任务详情。  
**使用角色**：全员。  
**前置条件**：已登录；用户 active；至少属于一个项目或被分配任务。  
**业务规则**：
1. 数据范围：`assignee_id = 当前用户`，且任务状态为 `todo/in_progress/in_review`，项目未归档，任务未软删除。
2. 排序：有截止日期优先，日期升序；同日按优先级 `urgent > high > medium > low`；无截止日期置后。
3. 首屏展示最多 10 条，提供“查看全部”跳转任务列表（预置 assignee=me）。
4. 显示任务编号、标题、项目、状态、优先级、截止日期、是否逾期。
5. 支持快速完成（仅 `in_progress/in_review` 且用户有更新权限时），完成后从列表移除并提示已更新；撤销需在任务详情中重新打开。
6. 不显示 `done/cancelled` 与已归档项目任务。

**输入字段**：无（读取）；可选筛选“仅逾期”。  
**输出结果**：待办列表、总数、逾期数、空状态；点击进入任务详情。  
**异常情况**：项目归档/任务删除后条目消失；加载失败显示重试；无权限任务不返回。  
**验收标准**：
- [ ] 分配给我且未完成的任务出现在列表，排序符合规则。
- [ ] 完成/取消后 1 次刷新内消失。
- [ ] 空状态文案与“去项目创建任务”入口正确。
- [ ] 分页/总数与任务列表口径一致。

### FR-WB-02 待我审批

**功能说明**：展示当前审批步骤审批人是我的申请，支持查看摘要并进入审批详情。  
**使用角色**：任何被解析为当前步骤审批人的用户（含管理员）。  
**前置条件**：已登录；存在 `status=active` 的实例步骤且 `approverId=当前用户`。  
**业务规则**：
1. 只显示实例 `running` 且步骤 `active` 的记录；申请人自己的申请不会出现在其待审批中（解析时已阻止）。
2. 显示申请类型、标题、申请人、部门、提交时间、已等待时长、当前步骤。
3. 排序：提交时间升序（先到先审），支持按类型筛选。
4. 首屏最多 10 条；点击进入审批详情；可在详情通过/驳回，不在列表直接审批（避免误操作）。
5. 通过后该条消失；驳回后消失；被管理员转交后从原审批人列表消失。
6. 角标数量 = 待审批总数，最多显示 `99+`。

**输入字段**：无；筛选 `application_type`。  
**输出结果**：待审批列表、总数、等待时长；空状态“当前没有待你审批的申请”。  
**异常情况**：申请已撤回/已处理但列表未刷新 → 进入详情返回“已处理”，并提示刷新；审批人停用 → 由管理员转交。  
**验收标准**：
- [ ] 仅当前步骤审批人可见。
- [ ] 通过/驳回/撤回后待办与角标同步更新。
- [ ] 非审批人直接访问详情返回 403/404。
- [ ] 倒序/正序规则一致，等待时长准确。

### FR-WB-03 消息通知

**功能说明**：站内通知中心，覆盖任务分配、审批请求、审批结果、评论提及（P1）、项目成员变更。  
**使用角色**：全员。  
**前置条件**：已登录。  
**业务规则**：
1. 通知字段：类型、标题、正文摘要、跳转链接、是否已读、创建时间。
2. 未读数显示在顶栏铃铛与工作台模块；最大显示 `99+`。
3. 点击通知标记单条已读并跳转；支持“全部已读”。
4. 通知只发给有权限的接收人；链接失效时展示“内容已删除/无权访问”，不泄露内容。
5. 首版不发送邮件/短信/推送；P1 增加。
6. 保留期首版不自动清理；上线前确定策略（见风险）。

**输入字段**：无；操作 `markRead`、`markAllRead`。  
**输出结果**：通知列表、未读数、已读状态、跳转。  
**异常情况**：跳转目标已删除 → 提示；标记已读失败 → 保留未读并允许重试。  
**验收标准**：
- [ ] 审批提交后当前审批人收到通知；审批完成后申请人收到结果通知。
- [ ] 点击后已读状态持久化，刷新不回退。
- [ ] 全部已读后角标清零。
- [ ] 无权限目标不泄露标题/正文。

### FR-WB-04 最近项目

**功能说明**：展示当前用户最近访问或参与的项目，提供快速回到工作现场。  
**使用角色**：全员。  
**前置条件**：用户是项目成员；项目未归档。  
**业务规则**：
1. 数据源：`project_members.last_viewed_at`；只统计当前用户作为成员的项目。
2. 只显示未归档、未删除项目；最多 6 个。
3. 排序：最近访问时间倒序；从未访问按加入时间/项目更新时间倒序。
4. 显示项目短键、名称、状态、我的项目角色、未完成任务数。
5. 点击项目即更新 `last_viewed_at`（同一天内可合并更新，避免高频写）。
6. 组织可见但非成员的项目不出现在“最近项目”，可在项目列表中查找；避免把“最近访问”变成隐式全局追踪。

**输入字段**：无。  
**输出结果**：项目卡片列表、空状态“还没有项目，创建一个或等待被邀请”。  
**异常情况**：项目归档/移除成员后不再显示；加载失败显示重试。  
**验收标准**：
- [ ] 最近访问的项目排在前面。
- [ ] 归档项目不出现。
- [ ] 非成员不能通过该模块看到私有项目。
- [ ] 空状态按钮按权限显示“创建项目”。

### FR-WB-05 工作概览

**功能说明**：以计数和轻量趋势展示“我的工作”与角色相关概况。  
**使用角色**：全员；管理者看到部门/项目聚合。  
**前置条件**：已登录。  
**业务规则**：
1. 个人指标：未完成任务数、本周到期数、本周完成数、待审批数、未读通知数、逾期任务数。
2. 部门负责人：额外显示本部门及子部门逾期任务数、待审批数（P1 可扩展）。
3. 项目负责人：额外显示负责项目的完成率、逾期任务数、待验收任务数。
4. 管理员：额外显示组织活跃用户数、待处理授权变更（若实现）、异常登录数（近 7 天）。
5. 统计口径按组织时区；本周为周一 00:00 至周日 23:59:59。
6. 数值为实时查询，不做缓存；查询失败模块级降级，不影响其他模块。

**输入字段**：无；时间范围固定“本周”。  
**输出结果**：指标卡、项目健康摘要、跳转链接。  
**异常情况**：部分模块失败 → 显示“暂时无法加载”并重试，不整页报错；数据为 0 时显示 0 而非空白。  
**验收标准**：
- [ ] 指标与源列表口径一致（抽样核对）。
- [ ] 不同角色看到的模块不同，且不泄露越权数据。
- [ ] 周一零点边界计算正确。
- [ ] 单模块失败不导致整页崩溃。

## 4. 项目管理（PRJ / TSK）

### FR-PRJ-01 项目创建与编辑

**功能说明**：创建项目并维护名称、短键、描述、可见性、起止日期与负责人。  
**使用角色**：普通成员（受组织配置限制）、组织管理员。  
**前置条件**：已登录；若组织关闭“成员可创建项目”，则需 `project:create` 权限。  
**业务规则**：
1. 必填：名称 2–80 字、短键 2–10 位大写字母/数字、可见性。
2. 短键组织内唯一（未删除项目）；创建后不可修改，避免任务编号失效。
3. 名称可修改；描述 ≤ 2000 字，Markdown。
4. 可见性：`private`（默认）或 `organization`；创建后可修改，改为 private 时非成员将失去访问。
5. 创建者自动成为 `owner` 并写入 `project_members`；项目状态初始 `planning`。
6. 起止日期可选；结束日期不得早于开始日期。
7. 项目编辑需 `owner/manager` 或组织管理员；每次修改写审计。
8. 项目不上传封面，首版不做图标/颜色自定义（使用短键色块）。

**输入字段**：`name`、`key`、`description`、`visibility`、`start_date`、`due_date`、`owner_id`（管理员可指定）。  
**输出结果**：项目详情；成员关系；审计记录；跳转项目任务页。  
**异常情况**：短键重复 → 409 `PROJECT_KEY_TAKEN`；无权限 → 403；日期非法 → 422；并发创建同名不阻止（名称不唯一）。  
**验收标准**：
- [ ] 创建后创建者为 owner，且能立即创建任务。
- [ ] 短键重复被拒绝且提示可操作。
- [ ] 修改可见性后，非成员访问行为符合规则。
- [ ] 日期校验与审计记录正确。

### FR-PRJ-02 项目成员

**功能说明**：管理项目成员及项目角色，支持添加、移除、变更角色、转让 owner。  
**使用角色**：项目 owner/manager；组织管理员。  
**前置条件**：项目存在且未归档；操作者有成员管理权限。  
**业务规则**：
1. 只能添加同组织 active 用户；支持按姓名/邮箱搜索，单次最多 20 人。
2. 项目角色：`owner`（唯一）、`manager`、`member`、`viewer`。
3. owner 不能被移除或降级，必须先转让；转让后原 owner 自动变为 `manager`。
4. manager 可添加/移除 member/viewer，不能移除其他 manager 或 owner；owner 可管理所有成员。
5. 移除成员时，其未完成任务需先转派或取消；否则返回 409 并列出任务数。
6. 成员被停用后自动失去访问，但其历史任务保留；项目负责人需转派。
7. 每次成员/角色变更写审计并通知被变更人。
8. 不允许把非组织用户加入项目（首版无访客）。

**输入字段**：`user_ids`、`project_role`；移除 `user_id`；转让 `new_owner_id`。  
**输出结果**：成员列表（姓名、部门、项目角色、加入时间、未完成任务数）；变更结果。  
**异常情况**：重复添加 → 幂等成功；移除 owner → 409；移除有未完成任务的成员 → 409；用户不存在/停用 → 422。  
**验收标准**：
- [ ] owner 唯一且不可直接移除。
- [ ] 转让 owner 原子完成，旧 owner 变为 manager。
- [ ] 移除成员前任务校验有效。
- [ ] 被添加成员能在“最近项目”看到项目。

### FR-PRJ-03 项目状态

**功能说明**：按状态机推进项目，支持暂停/恢复、完成、取消、归档。  
**使用角色**：owner/manager；归档与取消需 owner 或组织管理员。  
**前置条件**：项目存在；操作者有状态变更权限。  
**业务规则**：
1. 合法迁移：
   - `planning → active`（需至少 1 名成员，owner 已存在）
   - `active ↔ on_hold`
   - `active → completed`（无 `todo/in_progress/in_review` 任务）
   - `planning/active/on_hold → cancelled`（需填写原因）
   - `completed/cancelled → archived`（终态）
2. 不允许从 `archived` 回到其他状态；不允许跳过 `completed/cancelled` 直接归档进行中项目。
3. `completed` 后项目只读：不能新建/编辑任务、成员；可查看、导出（P1）。
4. `cancelled` 后任务不自动取消；需在取消前处理，或取消时选择“同时取消未完成任务”（需二次确认）。
5. 归档项目从默认列表隐藏；保留详情只读访问（有权限者）。
6. 状态变更写审计并通知成员；完成/取消需填写备注（≤500 字）。
7. 管理员可软删除项目，但必须无未完成任务且二次确认；软删除不物理删除。

**输入字段**：`target_status`、`reason`（取消/完成备注）、`cancel_open_tasks`（布尔）。  
**输出结果**：新状态、时间戳、审计；成员通知。  
**异常情况**：非法迁移 → 409 `PROJECT_STATE_INVALID`；有未完成任务完成 → 409 并返回数量；无权限 → 403；并发冲突 → 409 版本冲突。  
**验收标准**：
- [ ] 状态机所有合法/非法路径按规则执行。
- [ ] 有未完成任务时不能完成项目。
- [ ] 归档后项目只读且默认列表隐藏。
- [ ] 取消时“同时取消任务”行为一致。

### FR-TSK-01 任务管理

**功能说明**：在项目内创建、编辑、筛选、查看、删除任务。  
**使用角色**：项目成员（创建/编辑受限）；owner/manager（全量）。  
**前置条件**：项目未归档/未删除；用户是项目成员。  
**业务规则**：
1. 必填：标题 2–120 字；项目由上下文确定；状态默认 `todo`，优先级默认 `medium`。
2. 可选：描述（Markdown ≤10000）、负责人（同项目成员）、开始/截止日期、进度。
3. 任务编号 `PROJECT_KEY-N` 由项目内 `task_seq` 原子递增；不可修改。
4. 创建者可编辑标题/描述/优先级；被分配者可更新状态/进度；owner/manager 可编辑全部字段。
5. 负责人必须是项目成员且 active；可为空（待分配）。
6. 截止日期不得早于开始日期；允许过去日期（用于补录），逾期由查询计算。
7. 删除为软删除，仅 owner/manager；删除后从列表/看板消失，任务编号不复用。
8. 列表支持：关键词（标题）、状态、优先级、负责人、逾期、日期范围；默认按更新时间倒序。
9. 任务详情展示项目、编号、状态、负责人、日期、进度、评论数、操作记录入口（审计）。

**输入字段**：`title`、`description`、`status`、`priority`、`assignee_id`、`start_date`、`due_date`、`progress`、`version`。  
**输出结果**：任务详情/列表、任务编号、审计。  
**异常情况**：负责人非成员 → 422；项目归档 → 409；并发更新 → 409；无权限 → 403/404。  
**验收标准**：
- [ ] 任务编号连续且唯一（并发下不重复）。
- [ ] 成员只能改允许的字段，越权字段被 403。
- [ ] 筛选组合结果正确，逾期口径一致。
- [ ] 删除后任务从看板/搜索消失但审计可查。

### FR-TSK-02 任务看板

**功能说明**：按状态分列展示任务，支持拖拽改变状态与列内排序。  
**使用角色**：项目成员；viewer 只读。  
**前置条件**：项目存在；用户可查看项目。  
**业务规则**：
1. 列固定：待处理 `todo`、进行中 `in_progress`、待验收 `in_review`、已完成 `done`；`cancelled` 不在看板显示。
2. 列内排序使用 `board_order`（整数/十进制）；拖拽后服务端重排，返回新顺序。
3. 拖拽跨列即状态变更，必须满足状态机；拖到 done 自动进度 100；从 done 拖出需显式重置进度（默认 0）。
4. viewer 不能拖拽；无更新权限的成员只能拖拽自己创建/被分配的任务。
5. 每列显示数量；支持按负责人/优先级筛选；筛选后拖拽仍作用于真实状态。
6. 单列首屏最多 50 条，超出用“加载更多”；不做虚拟滚动（首版）。
7. 并发拖拽冲突：版本冲突返回 409，前端刷新该任务并提示。

**输入字段**：`task_id`、`target_status`、`target_index`、`version`。  
**输出结果**：更新后的任务状态/顺序；列计数。  
**异常情况**：非法状态迁移 → 409；任务已被他人移动 → 409 + 刷新；无权限 → 403；项目归档 → 409。  
**验收标准**：
- [ ] 四列展示与计数正确。
- [ ] 拖拽后刷新顺序保持。
- [ ] 非法迁移被拒绝且 UI 回滚。
- [ ] 并发拖拽不产生重复顺序/丢失任务。

### FR-TSK-03 任务进度

**功能说明**：维护任务 0–100 的进度，并与状态保持一致。  
**使用角色**：任务创建者、被分配者、owner/manager。  
**前置条件**：任务存在且未删除；项目未归档。  
**业务规则**：
1. 进度为整数 0–100；UI 用滑块 + 数字输入。
2. `status=done` 时进度强制 100；`status!=done` 时进度最多 99。
3. 将进度改为 100 时，若当前不是 done，提示并同时置为 done（需用户确认）；API 要求同一请求提交 `status=done`。
4. 将 done 改回其他状态时，必须显式提交 0–99 的进度；未提交则默认 0。
5. 进度变化写审计；同一天内高频拖动可在前端合并，落库只保留最后一次（需版本校验）。
6. 项目完成率按 `done / (总任务 - cancelled)` 计算；无有效任务时为 0，不显示 NaN。

**输入字段**：`progress`、`status`、`version`。  
**输出结果**：更新后的进度/状态；项目完成率刷新。  
**异常情况**：进度越界 → 422；done 与进度不一致 → 422；并发冲突 → 409。  
**验收标准**：
- [ ] 所有状态/进度组合符合约束。
- [ ] 100% 自动完成与重新打开行为正确。
- [ ] 项目完成率口径与列表一致。
- [ ] 进度变更可在审计中追溯。

### FR-TSK-04 任务评论

**功能说明**：项目成员围绕任务讨论，支持 Markdown、编辑与软删除。  
**使用角色**：项目成员（viewer 只读，不评论）；owner/manager 可管理。  
**前置条件**：任务存在；用户是项目成员且非 viewer。  
**业务规则**：
1. 评论 1–2000 字，支持 Markdown；不允许附件（P1）。
2. 作者可在发布后 15 分钟内编辑；超过 15 分钟不可编辑（管理员也不能改内容）。
3. 作者可删除自己的评论（软删除）；owner/manager/组织管理员可删除任意评论，需填原因。
4. 删除后 UI 显示“评论已删除”，不显示正文；审计保留操作者与时间。
5. 评论按时间正序；分页 20 条；新评论后刷新计数。
6. 评论不触发审批，不影响任务状态。
7. 提及 `@用户` P1；首版按纯文本处理。

**输入字段**：`content`、`task_id`；编辑 `content`；删除 `reason`。  
**输出结果**：评论列表、评论数、审计。  
**异常情况**：空内容/超长 → 422；编辑超时 → 409 `COMMENT_EDIT_WINDOW_EXPIRED`；无权限 → 403。  
**验收标准**：
- [ ] 评论发布后立即出现在列表。
- [ ] 15 分钟编辑窗口准确。
- [ ] 删除后正文不可见但审计可查。
- [ ] viewer 不能评论。

## 5. OA 审批（OA）

### 5.1 通用申请规则

所有申请共享：

- 状态：`draft/pending/approved/rejected/withdrawn`。
- 草稿仅申请人可见、可编辑、可删除；提交后不可编辑。
- 提交时校验必填、附件、审批模板、审批人可解析。
- 申请编号：`OA-YYYYMMDD-XXXX`（组织内唯一，按日序列）；展示用，不作为主键。
- 申请详情包含：类型、标题、申请人、部门快照、提交时间、状态、表单内容、附件、审批时间线。
- 撤回：仅在无人审批（无 approve/reject 记录）时可撤回；撤回后状态 `withdrawn`，不可再次提交，需复制新建。
- 驳回：终态；可复制新建。
- 审批人不能是申请人；解析失败则提交失败并提示。
- 通过/驳回必须二次确认；驳回意见必填 10–500 字。
- 附件：0–5 个，单个 ≤10MB，支持 PDF/JPG/PNG；上传后未提交的孤儿文件由 P1 清理任务处理。
- 表单字段版本：`formSchemaVersion` 随代码升级；旧申请按提交时版本渲染，不因新 schema 丢失字段。

### FR-OA-01 请假申请

**功能说明**：员工提交请假申请并走审批。  
**使用角色**：全员。  
**前置条件**：存在 active 的请假审批模板；审批人可解析；员工 active。  
**业务规则**：
1. 请假类型：年假、病假、事假、调休、婚假、产假、陪产假、丧假。
2. 开始/结束时间为组织时区；结束必须晚于开始；最长 365 天。
3. 时长由申请人填写，0.5 天步长；首版不自动排除周末/节假日、不扣减假期余额（工作日历/余额 P1）。
4. 原因 10–500 字；交接人可选（同组织 active 用户，不能是本人）。
5. 病假建议上传证明，但首版不强制。
6. 同一员工存在时间重叠的 `pending/approved` 请假时，提交返回 409 并提示冲突区间。
7. 默认审批链：直属上级 → 部门负责人；连续相同审批人自动合并为一步。

**输入字段**：`leaveType`、`startAt`、`endAt`、`durationDays`（服务端计算/校验）、`reason`、`handoverUserId`、`attachments`。  
**输出结果**：申请详情、审批实例、当前审批人、通知。  
**异常情况**：时间重叠 → 409；模板缺失 → 409；审批人缺失 → 422；附件超限 → 413/422；时长非 0.5 倍数 → 422。  
**验收标准**：
- [ ] 提交后生成审批实例，状态 `pending`。
- [ ] 重叠请假被拒绝并显示冲突。
- [ ] 审批通过/驳回后状态与历史正确。
- [ ] 申请人、审批人、管理员看到的数据范围正确。

**异常情况**：日期非法 → 422；项目无权/归档 → 422；金额越界 → 422；审批人缺失 → 422。  
**验收标准**：
- [ ] 关联项目只显示有权限项目。
- [ ] 费用精度与上限校验正确。
- [ ] 审批流转与请假一致。
- [ ] 项目详情可反查关联出差（P1 可做列表，R1 至少详情展示项目链接）。

### FR-OA-06 审批流程

**功能说明**：管理员配置审批模板与版本；申请人提交后生成顺序审批实例；审批人处理当前步骤。  
**使用角色**：组织管理员（模板）；申请人；当前步骤审批人；管理员（异常转交）。  
**前置条件**：模板 active 且至少 1 步；审批人可解析；实例 running。  
**业务规则**：
1. 模板字段：名称、申请类型、步骤列表、状态（draft/active/inactive）、版本号。
2. 每个类型同时只能有 1 个 active 模板；发布新版本后旧版本保留，进行中实例不受影响。
3. 步骤字段：序号、名称、审批人类型（`user`/`department_manager`/`direct_manager`）、固定用户（仅 user 类型）。
4. 提交时一次性解析所有步骤审批人并写入实例快照；后续组织变更不影响进行中实例。
5. 连续步骤解析为同一审批人时合并为一步；若解析结果为申请人、停用用户、空值，提交失败并指出步骤。
6. 同一时刻只有当前步骤 `active`；通过后激活下一步；最后一步通过 → 实例/申请 `approved`。
7. 驳回 → 当前步骤/实例/申请 `rejected`，后续步骤保持 `waiting`，不再激活。
8. 撤回 → 仅申请人、且尚无 approve/reject 记录；实例/申请 `withdrawn`。
9. 管理员转交：仅当前步骤，需 `workflow:reassign` 权限与原因；更新审批人并写 `reassign` 记录/审计/通知；不改变步骤序号。
10. 审批动作使用行锁/条件更新防止重复处理；重复提交返回 409。
11. 审批人只能看到自己待审批的申请详情；组织管理员可看全部。
12. 模板不能删除已被实例引用的版本；只能停用。

**输入字段**：
- 模板：`name`、`application_type`、`steps[]`、`status`；
- 提交：`applicationId`；
- 审批：`action`（approve/reject）、`comment`、`version`；
- 转交：`new_approverId`、`reason`。

**输出结果**：模板版本；实例与步骤；审批记录；申请状态；通知；审计。  
**异常情况**：无 active 模板 → 409；审批人解析失败 → 422；非当前审批人 → 403；重复审批 → 409；实例已结束 → 409；转交对象停用/非本组织 → 422。  
**验收标准**：
- [ ] 模板发布生成不可变版本，进行中实例不受影响。
- [ ] 顺序审批、驳回、撤回、转交路径全部正确。
- [ ] 并发重复审批只成功一次。
- [ ] 审批人不能审批自己；管理员不能无记录代批。
- [ ] 所有动作可在历史中追溯。

### FR-OA-07 审批历史

**功能说明**：以时间线展示申请的提交、每步审批、转交、撤回、驳回记录。  
**使用角色**：申请人、当前/历史审批人、组织管理员、审计员（摘要）。  
**前置条件**：用户有权查看该申请。  
**业务规则**：
1. 时间线按发生时间正序；每条含步骤名、动作、操作人、时间、意见、结果。
2. 记录不可编辑/删除；转交记录显示原审批人 → 新审批人及原因；原因对申请人可见，避免黑箱。
3. 当前步骤高亮；未激活步骤显示“等待中”，不显示审批人（避免绕过）。
4. 审批意见中的敏感内容按权限显示；审计员只看摘要（动作/时间/人），不看正文。
5. 支持导出 PDF/打印（P1）；首版仅页面查看。
6. 历史数据保留，不随用户停用/删除而消失；用户显示“已停用”。

**输入字段**：`applicationId`。  
**输出结果**：审批时间线、当前状态、当前审批人。  
**异常情况**：无权 → 404；申请不存在 → 404；数据不一致（历史缺失）→ 显示警告并记录错误日志，不伪造记录。  
**验收标准**：
- [ ] 提交、通过、驳回、撤回、转交均出现在时间线。
- [ ] 顺序与时间准确，意见完整。
- [ ] 非授权用户看不到时间线。
- [ ] 停用用户仍显示历史身份。

## 6. 组织管理（ORG）

### FR-ORG-01 组织架构

**功能说明**：以树形展示组织、部门、负责人、人数，提供导航入口。  
**使用角色**：全员查看；组织管理员管理。  
**前置条件**：已登录。  
**业务规则**：
1. 展示组织名、部门树、每个部门负责人、直属人数、总人数（含子部门）。
2. 全员可查看组织通讯录中的姓名、部门、岗位、工作邮箱；手机号默认仅本人/管理员可见。
3. 点击部门显示部门详情与成员列表；无权限的敏感字段隐藏。
4. 支持搜索部门/员工；搜索结果仍受权限过滤。
5. 部门树最多 10 层；循环引用禁止。
6. 组织架构变更后，成员列表与审批人解析即时生效（进行中实例不变）。

**输入字段**：搜索关键词；部门节点。  
**输出结果**：树、部门详情、成员列表。  
**异常情况**：部门为空 → 空状态；搜索无结果 → 提示；加载失败 → 重试。  
**验收标准**：
- [ ] 树层级、人数、负责人正确。
- [ ] 普通成员看不到手机号等敏感字段。
- [ ] 搜索不泄露越权数据。
- [ ] 组织架构变更后新申请使用新负责人。

### FR-ORG-02 部门管理

**功能说明**：维护部门树、负责人、排序与部门信息。  
**使用角色**：组织管理员。  
**前置条件**：`department:manage` 权限。  
**业务规则**：
1. 字段：名称 2–50 字、编码（可选，组织内唯一）、上级部门、负责人、排序、描述。
2. 部门名称在同一父级下唯一；编码全局唯一（未删除）。
3. 不能把部门设为自己的祖先（防循环）；最大深度 10。
4. 删除部门前必须：无子部门、无在职员工、无关联审批模板；否则 409 并列出原因。
5. 负责人必须是本部门或上级部门 active 用户；可为空。
6. 停用部门（P1）暂不做；首版只支持删除空部门。
7. 变更写审计；负责人变更影响后续审批解析。

**输入字段**：`name`、`code`、`parent_id`、`manager_id`、`sort_order`、`description`。  
**输出结果**：部门树、部门详情、审计。  
**异常情况**：重名 → 409；循环 → 422；有子部门/员工 → 409；深度超限 → 422。  
**验收标准**：
- [ ] 部门 CRUD 与排序正确。
- [ ] 循环/深度/删除约束生效。
- [ ] 负责人变更后新申请解析到新负责人。
- [ ] 删除失败提示具体原因。

### FR-ORG-03 员工管理

**功能说明**：查看/维护员工档案（不含账号安全操作）。  
**使用角色**：组织管理员；本人可查看/有限编辑自己的资料。  
**前置条件**：`employee:manage` 或本人。  
**业务规则**：
1. 字段：姓名、工作邮箱（只读，账号主键）、手机号、工号、部门、岗位、直属上级、入职日期、状态。
2. 工号组织内唯一（可空）；手机号格式校验；直属上级不能是本人，且不能形成汇报环。
3. 员工停用由系统管理执行；停用后档案只读，历史保留。
4. 本人可编辑头像、手机号（若组织允许）；不能改部门/岗位/上级/工号。
5. 部门/岗位必须存在且未删除；岗位与部门无强制绑定。
6. 列表支持按部门（含子部门）、岗位、状态、关键词筛选。
7. 导出员工列表 P1；首版不提供批量导出（降低泄露风险）。

**输入字段**：`name`、`phone`、`employee_no`、`department_id`、`position_id`、`manager_id`、`hire_date`。  
**输出结果**：员工列表/详情、审计。  
**异常情况**：工号重复 → 409；汇报环 → 422；部门/岗位无效 → 422；无权限字段隐藏。  
**验收标准**：
- [ ] 档案字段校验与唯一性正确。
- [ ] 汇报环被拒绝。
- [ ] 本人只能改允许字段。
- [ ] 部门筛选含子部门。

### FR-ORG-04 岗位管理

**功能说明**：维护岗位目录，供员工档案引用。  
**使用角色**：组织管理员。  
**前置条件**：`position:manage`。  
**业务规则**：
1. 字段：名称 2–50 字、编码（组织内唯一）、描述、排序。
2. 岗位名称组织内唯一（未删除）。
3. 删除前必须无在职员工引用；否则 409。
4. 岗位不直接授予权限；权限仍由角色决定。
5. 支持启用/停用（停用后不可再分配，已分配保留）。

**输入字段**：`name`、`code`、`description`、`sort_order`、`status`。  
**输出结果**：岗位列表、审计。  
**异常情况**：重名/重码 → 409；被引用删除 → 409；无权限 → 403。  
**验收标准**：
- [ ] 岗位 CRUD 与唯一性正确。
- [ ] 被引用岗位不能删除。
- [ ] 停用岗位不出现在新分配下拉。

### FR-ORG-05 角色管理

**功能说明**：创建/维护自定义角色、复制内置角色、设置数据范围。  
**使用角色**：组织管理员。  
**前置条件**：`role:manage`。  
**业务规则**：
1. 内置角色：`member`、`org_admin`、`system_admin`、`auditor`；不可删除/改名/改权限。
2. 自定义角色：名称 2–30 字、编码自动生成、描述、数据范围。
3. 数据范围：`self`、`department`、`department_tree`、`organization`；自定义角色默认 `self`。
4. 复制内置角色时复制权限码，但不复制用户分配。
5. 删除角色前必须无 `user_roles` 引用；否则 409 并显示人数。
6. 不能创建比创建者权限更高的角色（权限子集校验）。
7. 角色变更写审计；影响所有持有者，需二次确认。

**输入字段**：`name`、`description`、`data_scope`、`permission_codes[]`、`copy_from_role_id`。  
**输出结果**：角色列表/详情、权限预览、审计。  
**异常情况**：重名 → 409；越权授予 → 403；删除被引用角色 → 409；内置角色修改 → 403。  
**验收标准**：
- [ ] 内置角色不可修改。
- [ ] 自定义角色权限/数据范围正确生效。
- [ ] 删除引用校验有效。
- [ ] 不能通过创建角色提权。

### FR-ORG-06 权限管理

**功能说明**：查看权限目录、角色-权限矩阵与“某人能做什么”的有效权限预览。  
**使用角色**：组织管理员；审计员只读。  
**前置条件**：`role:manage` 或 `permission:read`。  
**业务规则**：
1. 权限目录由代码定义，UI 只读；按模块分组，显示 code、名称、说明。
2. 角色-权限矩阵支持勾选（自定义角色）与查看（内置角色）；保存走角色更新接口。
3. 有效权限预览：选择用户，展示系统角色并集、部门派生能力、项目角色摘要、数据范围；不展示他人未授权资源明细。
4. 权限变更立即生效；下一次请求重新计算，不依赖前端缓存。
5. 高风险权限（`org_admin`、`role:manage`、`audit:read`、`workflow:reassign`）单独标识，授予需二次确认。
6. 首版不提供权限码自定义/字段级权限。

**输入字段**：`role_id`、`permission_codes[]`；预览 `user_id`。  
**输出结果**：权限目录、矩阵、有效权限说明、审计。  
**异常情况**：未知权限码 → 422；内置角色保存 → 403；预览用户不存在 → 404；无权限 → 403。  
**验收标准**：
- [ ] 目录与代码权限码一致（自动测试）。
- [ ] 矩阵保存后权限立即生效。
- [ ] 有效权限预览能解释“为什么能/不能”。
- [ ] 高风险权限操作有二次确认与审计。

## 7. 系统管理（SYS）

### FR-SYS-01 用户管理

**功能说明**：创建、停用、重置密码、强制下线、查看用户账号状态。  
**使用角色**：系统管理员、组织管理员。  
**前置条件**：`user:manage`。  
**业务规则**：
1. 创建用户：姓名、工作邮箱、部门、岗位、直属上级、初始角色（默认 member）。
2. 邮箱组织内唯一（不区分大小写）；必须是有效邮箱格式。
3. 系统生成 16 位临时密码，仅在创建成功页展示一次；用户首次登录强制改密。
4. 停用用户：立即撤销全部会话；不能停用最后一个组织管理员；若用户是进行中审批的当前审批人，必须先转交。
5. 重置密码：生成新临时密码，撤销全部会话，强制下次改密。
6. 强制下线：撤销全部会话，不改变密码。
7. 用户不可物理删除；停用后历史记录保留，显示“已停用”。
8. 管理员不能停用自己（避免误锁），需另一管理员操作。

**输入字段**：`name`、`email`、`department_id`、`position_id`、`manager_id`、`role_ids[]`；操作 `disable`、`resetPassword`、`forceLogout`。  
**输出结果**：用户列表/详情、临时密码（一次）、审计。  
**异常情况**：邮箱重复 → 409；最后管理员 → 409；当前审批人 → 409 并列出申请；停用自己 → 409。  
**验收标准**：
- [ ] 创建后可用临时密码登录并强制改密。
- [ ] 停用/重置/强制下线立即撤销会话。
- [ ] 最后管理员与当前审批人保护生效。
- [ ] 临时密码不再可查。

### FR-SYS-02 角色权限

**功能说明**：给用户分配/撤销系统角色，查看有效权限，处理离职移交。  
**使用角色**：组织管理员（角色分配由组织管理员负责；系统管理员无角色分配权）。  
**前置条件**：`user:manage` + `role:manage`。  
**业务规则**：
1. 一个用户至少 1 个角色；默认 `member`。
2. 分配角色时校验操作者权限子集；不能授予自己没有的权限。
3. 只有组织管理员能授予/撤销 `org_admin`、`system_admin`、`auditor`；不能撤销自己的最后一个管理员角色。
4. 角色变更立即生效并撤销该用户的权限缓存（若有）；写审计。
5. 离职移交：停用前需转移项目 owner、转交当前审批、处理未完成任务；提供检查清单。
6. 支持按角色查看成员；支持批量分配（最多 50 人）。
7. 首版不做临时授权/到期自动回收（P1）。

**输入字段**：`user_id`、`role_ids[]`；批量 `user_ids[]`。  
**输出结果**：用户角色、有效权限、审计。  
**异常情况**：越权授予 → 403；最后管理员 → 409；角色不存在 → 422；批量部分失败 → 事务全失败并返回明细。  
**验收标准**：
- [ ] 分配/撤销后权限立即变化。
- [ ] 不能提权、不能删除最后管理员。
- [ ] 离职检查清单覆盖项目/审批/任务。
- [ ] 批量操作原子性正确。

### FR-SYS-03 登录记录

**功能说明**：记录并查询登录成功/失败尝试。  
**使用角色**：系统管理员、组织管理员、审计员（只读）。  
**前置条件**：`login:read`。  
**业务规则**：
1. 记录：时间、邮箱尝试、用户（成功时）、结果、失败原因（账号不存在/密码错误/已停用/锁定）、IP、User-Agent。
2. 失败原因对外统一为“邮箱或密码错误”；管理端可看细分原因，但不记录密码。
3. 支持按时间、邮箱、结果、IP 筛选；默认近 7 天；最大跨度 90 天。
4. 记录不可修改/删除；保留期上线前确定（建议 180 天）。
5. 连续失败锁定：同一邮箱 5 次失败锁 15 分钟；同一 IP 20 次/10 分钟限流；锁定事件写记录。
6. 导出 P1；首版页面查看。

**输入字段**：`from`、`to`、`email`、`result`、`ip`、分页。  
**输出结果**：登录记录列表、总数、详情。  
**异常情况**：时间跨度超限 → 422；无权限 → 403；记录为空 → 空状态。  
**验收标准**：
- [ ] 成功/失败/锁定均记录。
- [ ] 不记录明文密码/令牌。
- [ ] 筛选与时间跨度限制正确。
- [ ] 审计员只读。

### FR-SYS-04 操作日志

**功能说明**：记录关键写操作与授权变更，支持查询详情。  
**使用角色**：系统管理员、组织管理员、审计员（只读）。  
**前置条件**：`audit:read`。  
**业务规则**：
1. 记录：时间、操作人、动作、资源类型/ID、结果、IP、User-Agent、请求 ID、变更摘要。
2. 覆盖：登录/登出、用户/角色/权限变更、项目/任务状态变更、申请提交/审批/转交、文档上传/授权/删除、系统配置变更。
3. 敏感字段（密码、令牌、文件内容）永不记录；申请正文按字段白名单记录摘要或仅记录“已提交”。
4. 日志只追加；不提供 UPDATE/DELETE API；数据目录 ACL 限制。
5. 筛选：时间、操作人、动作、资源类型、结果、请求 ID；默认近 7 天，最大 90 天。
6. 详情展示变更前后字段（已脱敏）；不展示完整 Markdown 正文。
7. 导出 P1；首版不做。

**输入字段**：筛选条件、分页。  
**输出结果**：日志列表、详情、请求 ID。  
**异常情况**：跨度超限 → 422；无权限 → 403；日志缺失 → 显示“无记录”，不伪造。  
**验收标准**：
- [ ] 关键操作 100% 有日志（按清单测试）。
- [ ] 日志不可通过 API 修改/删除。
- [ ] 敏感字段不出现在日志。
- [ ] 请求 ID 可关联错误响应。

### FR-SYS-05 系统配置

**功能说明**：维护组织级基础配置与安全/文件/项目默认值。  
**使用角色**：系统管理员；组织管理员可查看。  
**前置条件**：`setting:manage`。  
**业务规则**：
1. 配置项受控，不允许任意 key：
   - `org.display_name`：组织显示名，2–80 字；
   - `org.timezone`：IANA 时区，默认 `Asia/Shanghai`；
   - `security.session_idle_minutes`：15–1440，默认 480；
   - `security.session_absolute_days`：1–30，默认 7；
   - `file.max_upload_mb`：1–100，默认 25；
   - `project.default_visibility`：`private`/`organization`，默认 private；
   - `project.allow_member_create`：布尔，默认 true；
   - `workflow.allow_self_approval`：固定 false，只读展示（不可开启）。
2. 保存前校验类型/范围；安全相关变更需二次确认并写审计。
3. 会话配置对新会话生效；已有会话的空闲/绝对过期按新值重新计算（需在文档中明确）。
4. 时区变更影响“今天/本周”统计与日期展示，不改变已存 UTC 时间。
5. 配置不存储密钥；SMTP、S3 等密钥走环境变量。
6. 首版不提供主题、Logo、登录页定制。

**输入字段**：上述配置键值。  
**输出结果**：配置生效、审计。  
**异常情况**：非法 key/值 → 422；无权限 → 403；并发保存 → 409。  
**验收标准**：
- [ ] 配置范围校验正确。
- [ ] 时区/会话变更行为符合说明。
- [ ] 安全配置变更写审计。
- [ ] 不能通过配置开启自审批。

## 8. 文档中心（完整范围）

> 文档中心按完整业务需求规划：文件管理、分类标签、搜索、权限、版本；不做事先缩减范围的人为最小闭环拆分。开发顺序可后置，但不是功能范围缩减。

### FR-DOC-01 文件管理（上传/下载/归档）

**功能说明**：上传办公文件，维护元数据，下载与归档。  
**使用角色**：全员（受 ACL）；文档所有者/管理员。  
**前置条件**：已登录；有目标分类/项目的访问权。  
**业务规则**：
1. 单次上传 1 个文件；标题默认文件名（可改，2–100 字）；描述 ≤1000 字。
2. 允许类型：PDF、DOC/DOCX、XLS/XLSX、PPT/PPTX、PNG、JPG/JPEG、TXT、MD、CSV；禁止可执行文件、HTML、SVG、脚本。
3. 单文件 ≤25MB（可配置 1–100MB）；服务端校验扩展名 + MIME + 文件头，不只信 Content-Type。
4. 存储 key 由服务端生成，不使用原始文件名作为路径；文件不在 Web 根目录直接暴露。
5. 可见性：`organization`（全员可读）、`project`（项目成员可读）、`restricted`（仅所有者 + 显式 ACL）。
6. 项目文档必须关联用户有权限的项目；项目归档后文档只读。
7. 下载必须经过鉴权；响应 `Content-Disposition: attachment`，文件名做安全编码。
8. 归档文档的内容/版本/ACL 只读、默认列表隐藏；所有者/`manage`/组织管理员仍可软删除（二次确认），删除后 UI 不提供恢复。
9. 首版不做在线预览、在线编辑、批量上传、拖拽文件夹。

**输入字段**：`file`、`title`、`description`、`category_id`、`projectId`、`visibility`、`tag_ids[]`。  
**输出结果**：文档详情、版本 1、下载链接（短时有效）、审计。  
**异常情况**：类型/大小不符 → 415/413；分类/项目无权 → 403/422；存储失败 → 500 并清理临时文件；同名文件允许（标题不唯一）。  
**验收标准**：
- [ ] 上传后能下载且内容校验一致（SHA-256）。
- [ ] 非法类型/超大文件被拒绝。
- [ ] 三种可见性访问行为正确。
- [ ] 归档/删除后默认列表不可见。

### FR-DOC-02 分类与标签

**功能说明**：用树形分类与扁平标签组织文档。  
**使用角色**：文档所有者、组织管理员；分类管理需 `document:category:manage`。  
**前置条件**：已登录；管理操作需权限。  
**业务规则**：
1. 分类：名称 2–50 字、父分类、排序；同父级下名称唯一；最大深度 5；禁止循环。
2. 删除分类前必须无文档、无子分类；否则 409。
3. 标签：名称 1–20 字、颜色（预设 8 色）；组织内名称不区分大小写唯一。
4. 一个文档最多 1 个分类、10 个标签；标签可多选。
5. 分类/标签删除不影响文档内容；删除标签自动解除关联。
6. 分类树全员可读；仅管理员可维护（首版不做个人分类）。

**输入字段**：`name`、`parent_id`、`sort_order`；标签 `name`、`color`；文档 `category_id`、`tag_ids[]`。  
**输出结果**：分类树、标签列表、文档分类/标签、审计。  
**异常情况**：重名 → 409；循环/深度 → 422；被引用删除 → 409；标签超 10 → 422。  
**验收标准**：
- [ ] 分类树/标签 CRUD 正确。
- [ ] 唯一性与深度/循环约束生效。
- [ ] 文档分类/标签保存与筛选正确。
- [ ] 删除分类/标签的引用保护有效。

### FR-DOC-03 文档搜索

**功能说明**：按标题、标签、分类、项目、所有者检索有权限的文档。  
**使用角色**：全员（结果受 ACL 过滤）。  
**前置条件**：已登录。  
**业务规则**：
1. 关键词匹配标题（不区分大小写，`ILIKE`），不搜索正文（全文检索 P1）。
2. 筛选：分类（含子分类）、标签、项目、所有者、可见性、更新时间范围。
3. 排序：相关度（标题精确 > 前缀 > 包含）→ 更新时间倒序；首版简化为更新时间倒序 + 标题匹配优先。
4. 结果必须先去权：用户无 view 权限的文档不返回，即使标题匹配。
5. 分页 20；返回标题、分类、标签、所有者、更新时间、当前版本号、大小。
6. 搜索输入长度 1–100；空关键词返回最近文档（有权限）。
7. 首版不做保存搜索、搜索历史、全文高亮。

**输入字段**：`q`、`category_id`、`tag_ids[]`、`projectId`、`owner_id`、`visibility`、`from`、`to`、分页。  
**输出结果**：文档列表、总数、空状态。  
**异常情况**：关键词超长 → 422；分类不存在 → 空结果；无权限结果被过滤；查询失败 → 重试。  
**验收标准**：
- [ ] 搜索结果不含越权文档（重点安全测试）。
- [ ] 标题匹配/筛选组合正确。
- [ ] 空关键词返回最近文档。
- [ ] 分类含子分类筛选生效。

### FR-DOC-04 文档权限控制

**功能说明**：管理文档可见性与用户/角色/部门 ACL。  
**使用角色**：文档所有者、`manage` 授权者、组织管理员。  
**前置条件**：文档存在；操作者有 manage 权限。  
**业务规则**：
1. 权限级别：`view` < `edit` < `manage`；高等级包含低等级。
2. 授权对象三选一：用户、系统角色、部门（含子部门可选）。
3. 所有者始终拥有 `manage`；组织管理员始终可管理；不能移除所有者的管理权。
4. `restricted` 文档仅所有者 + 显式 ACL；`project` 文档继承项目成员 view；`organization` 文档全员 view。
5. 显式 ACL 只能扩大访问，不能缩小继承权限（首版无 deny）。
6. 授权/撤销即时生效；写审计，不发送通知（P1 可增加通知）。
7. 不能把文档授权给停用用户/空部门；部门删除前需处理关联 ACL。
8. 首版不做公开链接、密码分享、到期授权。

**输入字段**：`visibility`；ACL `subject_type`（user/role/department）、`subject_id`、`permission`；撤销 `acl_id`。  
**输出结果**：ACL 列表、有效权限预览、审计。  
**异常情况**：重复授权 → 幂等更新；越权授权 → 403；授权对象无效 → 422；不能移除所有者 → 409。  
**验收标准**：
- [ ] 三种可见性 + 显式 ACL 的访问矩阵正确。
- [ ] 角色/部门授权对成员生效。
- [ ] 撤销后立即失去访问。
- [ ] 无 manage 权限不能改 ACL。

### FR-DOC-05 版本管理

**功能说明**：上传新版本，保留历史版本，下载任意历史版本。  
**使用角色**：有 `edit` 权限者、所有者、管理员。  
**前置条件**：文档存在且未归档；用户有 edit 权限。  
**业务规则**：
1. 每次上传新文件生成递增版本号 `1..N`；版本不可修改/删除。
2. 新版本成为当前版本；旧版本仍可下载；版本记录含文件名、大小、SHA-256、上传人、时间、备注（≤200 字）。
3. 上传新版本不改变文档标题/分类/ACL，除非同请求显式修改。
4. 版本号并发递增需加锁/唯一约束；冲突重试。
5. 首版不做版本恢复、版本对比、在线预览；恢复 P1（复制旧文件为新版本）。
6. 文档软删除后版本文件保留（审计/恢复），物理清理由 P1 运维任务处理。

**输入字段**：`file`、`version_note`；下载 `version_id`。  
**输出结果**：新版本、版本列表、下载链接、审计。  
**异常情况**：文件非法 → 415/413；并发版本冲突 → 409 重试；无 edit → 403；归档 → 409。  
**验收标准**：
- [ ] 版本号连续且唯一。
- [ ] 当前版本指向最新，历史可下载。
- [ ] 旧版本内容不可被覆盖。
- [ ] 版本记录包含校验和与上传人。

## 10. 非功能需求

### 10.1 性能

| 指标 | 目标 |
|---|---|
| 列表/详情 API P95 | ≤300ms（5 万任务/10 万申请以内） |
| 工作台首屏 API P95 | ≤500ms（聚合 5 个模块） |
| 页面首次可交互 | ≤2s（内网/常规宽带） |
| 看板 500 任务 | 滚动/拖拽无明显卡顿 |
| 文件上传 | 25MB 在 60s 内完成（视网络） |

### 10.2 可用性与可靠性

- 单机部署目标可用性 99.5%（尽力而为，不承诺 SLA）。
- 不建设自动/异地备份；不提供 RPO/RTO 承诺。
- 健康检查：`/health/live`、`/health/ready`。
- 优雅退出：停止接收新请求，等待进行中请求 ≤10s。
- 错误不丢失：5xx 记录 request_id、路由、用户 ID（不记录敏感数据）。

### 10.3 安全

- 密码 Argon2id；最小长度 12；禁止常见弱密码。
- 会话 Cookie：HttpOnly、SameSite=Lax；本地 HTTP 不设 Secure。
- CSRF：SameSite + Origin 校验 + CSRF token（见安全设计）。
- 登录限流/锁定；审计登录失败。
- 所有输入 Zod 严格校验；Markdown 白名单过滤；存储层键编码/转义；禁止原型污染键。
- 文件类型/大小/文件头校验；下载鉴权；禁止路径穿越。
- 权限矩阵与 IDOR 测试为发布门禁。

### 10.4 部署与环境

- 单组织、单台服务器；Windows 本机优先。
- 不要求安装 SQL 数据库/独立数据库服务；不使用 Docker/Kubernetes。
- 数据存本机 `data/` 目录；程序与数据分离；单端口提供 SPA + API。
- 默认仅本机 127.0.0.1；局域网需显式配置，本地 HTTP 明文风险由用户确认。
- 日志、临时文件、回收站有独立目录；不提供备份系统。

### 10.5 兼容性

- 桌面：Chrome/Edge 最近 2 个 major、Safari 最近 2 个 major、Firefox ESR。
- 平板/手机：iOS Safari、Android Chrome 最近 2 个 major。
- 不支持 IE。
- 最小视口 360px；核心审批/任务操作可用。

### 10.6 可访问性

- 键盘可完成登录、导航、表单、审批。
- 焦点可见；对比度 ≥4.5:1；表单 label/错误关联。
- 状态不只靠颜色。
